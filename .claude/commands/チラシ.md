## 紙面の骨格

A4たて 210×297mm・`padding:8.5mm 10mm`。上から

1. **ヘッダ** — ひらがなの大タイトル＋漢字の副題、右に「この1枚は〜」と通す数
2. **リード帯** — その単元の一番大事な1文（色の薄い背景）
3. **3セクション** — `.secs{display:flex;flex-direction:column;flex:1;min-height:0;justify-content:space-between}` で余白を自動配分。各セクションは ①②③ の丸番号＋見出し＋`.body`（`padding-left:11mm`）
4. **「おぼえておく」帯** — 上に太い横罫、✓付き4項目を2列

本文 3.1〜3.6mm、見出し 5.6〜6.2mm、数字チップ 4〜5mm。**本文は 3mm を下回らせない**（トイレで読めなくなる）。

## 印刷CSS（ここを間違えると全部やり直し）

```css
@page{ size:210mm 297mm; margin:0; }
@media print{
  html,body{ margin:0; padding:0; width:210mm; background:#fff;
    display:block; -webkit-print-color-adjust:exact; print-color-adjust:exact; }
  .hint{ display:none; }
  .sheet{ box-shadow:none; margin:0; width:210mm; height:296.8mm;
    transform:none; overflow:hidden; break-inside:avoid; break-after:avoid; page-break-after:avoid; }
}
/* 画面用の縮小。screen を書き忘れると印刷も46%に縮む（実際にやらかした） */
@media screen and (max-width:860px){
  .sheet{ transform-origin:top center; transform:scale(.46); margin-bottom:-160mm; }
}
```

- 高さは **297mm ちょうどにしない**（296.8mm）。端数で白紙の2ページ目が出る。
- `print-color-adjust:exact` は `body` にも。これで「背景のグラフィックを印刷」のチェックが外れていても色が出る。
- `@media (max-width:860px)` に **`screen` を必ず付ける**。印刷時の用紙幅は約794pxなのでこの条件に一致してしまう。

## 作る → 確認 のループ（毎回やる）

書いたら必ずPDFにして**目で見る**。CSSの計算だけで済ませない。

```bash
cd ~/Desktop/学習プリント/算数
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --disable-gpu \
  --no-pdf-header-footer --virtual-time-budget=8000 \
  --print-to-pdf="<名前>_A4.pdf" "file://$(python3 -c "import urllib.parse,sys;print(urllib.parse.quote(sys.argv[1]))" "$PWD/<名前>_A4.html")"

python3 -c "
import re
d=open('<名前>_A4.pdf','rb').read()
m=re.search(rb'/MediaBox\s*\[([^\]]*)\]', d); b=[float(x) for x in m.group(1).split()]
print('pages:', len(re.findall(rb'/Type\s*/Page[^s]', d)), '| mm:', round(b[2]*25.4/72,1),'x',round(b[3]*25.4/72,1))
"
sips -s format png --resampleWidth 1050 "<名前>_A4.pdf" --out <scratchpad>/check.png
```

**必ず `pages: 1` と `209.9 x 297.0` を確認**してから、PNGを `Read` で目視。見るところ:

- **はみ出し・重なり**（下の帯に食い込んでいないか）
- **SVGの右端ラベルの切れ**（`viewBox` の幅を超えていないか。「4通り」が「4通」になっていた）
- 行末の孤立文字、図と文字の重なり
- 表の桁・ドットの**間隔が不揃い**になっていないか（座標のベタ書きミス）

### はみ出したときの原因（この順で疑う）

1. **`<p>` のデフォルト余白** → CSSの先頭に `p{margin:0}` を入れる。これだけで25mm縮んだことがある。
2. `.secs` に `justify-content:space-between` を使っていると、はみ出しても見た目で気づきにくい。JSで測る:
   ```javascript
   const f=document.querySelector('.secs');
   (f.clientHeight - f.scrollHeight) / (96/25.4)   // マイナスならはみ出し（mm）
   ```
3. 左カラムが狭くて見出しが折り返している（grid の1列目を広げる）
4. 文章が長い → 削る。**フォントを小さくして逃げない。**

逆に**余白が余りすぎ**のときは、図と数字を大きくして埋める（遠くから読む紙なので大きいほどよい）。

## 内容の作り方

- **教科書の写真をもらったら、例題の順番・用語・求め方をそのままなぞる。**
  教科書にない解法は入れない（すだれ算は載っていなかったので外した）。
  手書きメモをもらったら、**そこに書かれた解き方を軸にする**（差集め算は「差の表」から「□の式＋ルール①〜④」に作り直した）。
- **1枚を1組の数で通す。** 約数=12と18／倍数=3と4／通分=2/3と3/4／大きな数=3億6500万。
  前の紙と数字をそろえると回が繋がる（倍数の12がそのまま通分の分母になる、など）。
- 構成は **定義 → 求め方 → 応用・まちがえやすい** の3段。最後に「おぼえておく」。
- **練習問題は入れない**（一度提案して断られている）。
- **答えは必ず自分で計算し直す。** 検算したことを報告に書く。
- 「1/2」と書くと分数レンダリングで崩れる場面がある → 文章中は「半分」。
- 他の紙への案内を1行入れる（「線分図でとく和差算…はもう1枚のチラシへ」）。

## 1枚に入りきらないとき

**勝手に縮めない。** 枚数の選択肢を日本語で出して聞く。
特殊算5単元のときは「①線分図でそろえる（和差算・分配算・消去算）／②数えかた（植木算・方陣算）」の
2枚に分けた。**分け方に意味がある切り口**を探すこと（性質が同じものをまとめる）。

## ANRINOアプリのチラシ集に載せる

1. **コピーして変換する**（この変換をしないと文字化け＋スマホで極小になる）
   原本は Artifact 公開前提で書いていて `<!DOCTYPE>` も `<meta charset>` も viewport も無い。
   ```bash
   cp "~/Desktop/学習プリント/算数/<名前>_A4.html" ~/Desktop/開発/ena-quiz/chirashi/<key>.html
   cp "~/Desktop/学習プリント/算数/<名前>_A4.pdf"  ~/Desktop/開発/ena-quiz/chirashi/<key>.pdf
   ```
   そのうえで、**最初の `</style>` までを head とみなして**包む:

   ```python
   HEAD = ('<!DOCTYPE html>\n<html lang="ja">\n<head>\n'
           '<meta charset="utf-8">\n'
           '<meta name="viewport" content="width=device-width, initial-scale=1">\n')
   TAIL = """
   <style>
   @media screen and (max-width:860px){
     body{ padding:8px 0 28px; }
     .sheet{ transform:scale(var(--fit,.46)) !important;
             margin-bottom:calc(-297mm * (1 - var(--fit,.46))) !important; }
   }
   </style>
   <script>
   (function(){
     function fit(){
       var w = Math.min(document.documentElement.clientWidth, 860);
       document.documentElement.style.setProperty('--fit', Math.min(1,(w-10)/793.7).toFixed(4));
     }
     fit(); addEventListener('resize', fit); addEventListener('orientationchange', fit);
   })();
   </script>
   </body>
   </html>
   """
   s = io.open(path, encoding='utf-8').read()
   i = s.index('</style>') + len('</style>')
   io.open(path,'w',encoding='utf-8').write(HEAD + s[:i] + '\n</head>\n<body>\n' + s[i:] + TAIL)
   ```

   原本の `scale(.46)` は固定なのでタブレットで小さすぎる。上書きで端末幅に合わせる。**印刷CSSには触れない。**
   確認は `document.characterSet === 'UTF-8'`・`clientWidth` が端末幅（980ではない）・横スクロール0の3点。

2. **サムネイル**
   ```bash
   cd ~/Desktop/開発/ena-quiz/chirashi
   sips -s format png --resampleWidth 420 <key>.pdf --out thumb/<key>.png
   ```

3. **一覧に足す** — `chirashi.html` の `SHEETS`（`g1`=算数のきほん / `g2`=とくしゅ算）に
   `{ k:'<key>', n:'ひらがな名', kj:'漢字の副題', c:'#色', d:'説明' }` を1行。

4. **デプロイ・確認**
   ```bash
   export NVM_DIR="$HOME/.nvm" && source "$NVM_DIR/nvm.sh"
   cd ~/Desktop/開発/ena-quiz && vercel --yes --prod
   curl -s -o /dev/null -w '%{http_code} %{content_type}\n' https://ena-quiz.vercel.app/chirashi/<key>.html
   ```
   ブラウザペインで `chirashi.html` を開き、**幅390pxでも横スクロールが出ないこと**を確認して `desktop` に戻す。

   ※ ローカル確認は Desktop 配下で `http.server` を立てると全部404になる。
   スクラッチパッドにコピーしてから配信する。
